# Results: what each file contains

All files here are generated by `code/tools/export_public_repo.py` from the working folders. Do not edit them by hand.

## `alternate_apo_states.csv` (and `.json`)

One row for each protein. 42 rows.

| Column | Meaning |
|---|---|
| `entry` | RelaxDB entry name. `_CPMG` marks the 10 proteins with CPMG data. |
| `set` | `CPMG-10` or `RelaxDB-133`. |
| `protein` | Protein, organism and construct, as we identified them from the entry sequence. |
| `call` | `yes`, `possible`, `unknown` or `no_evidence`. The rules are in the main README. |
| `literal_two_peak` | Does the evidence meet the literal definition (two separate peaks)? `qualifies`, `does not` or `cannot tell`, with the reason. Where the paper prints both kex and Δω, the computed regime is given next to the authors' words. |
| `reference_state` | The sample that counts as the free APO protein for this entry, with its conditions. |
| `kex`, `pB`, `regime` | Exchange rate, minor-state population and exchange regime, as printed in the source, with the evidence row. |
| `residues` | Residues or regions with the exchange. |
| `structure_match` | Deposited structures that the papers relate to the minor state, and what the relation is. |
| `evidence_rows`, `judgments` | IDs of the rows and judgments that support the call. |
| `caveats` | Limits that change how to read the call. |

## `judgments/<entry>.json`

One file for each protein. A judgment is one claim about one region, in one time window, in one sample state. Each judgment has a verdict (`dynamic_in_window`, `no_evidence_in_window`, `unresolved` and others), the detection details (method, kex, pB, Δω, field, temperature) and the evidence rows it uses. `protein_summary` gives the short answer and the open conflicts. The field rules are in `code/schema/judgment_contract.json`.

## `evidence_rows_cpmg10.csv` and `evidence_rows_relaxdb133.csv`

One row for each paper, experiment and condition. 597 rows for the CPMG proteins and 1,171 rows for the RelaxDB-133 proteins.

- `ID` stays the same between versions. Judgments use it.
- `Review priority`: `A` rows carry the call, `B` rows support it, `C` rows are background and are in the appendix.
- `What we read`: `full_text`, `si` (supplementary information) or `abstract_only`. A row from an abstract cannot carry a call on its own.
- `Organism / construct vs entry`: `target`, `same_protein_other_construct` or `homolog`, then the construct.
- `Location in paper` and the quote let a reader find the source sentence.
- `Expert check` columns are empty. No person has checked the rows yet.

## `pdb_states/<entry>.md`

One table for each CPMG protein. Each row is one chain of one deposited structure: its class (apo, ligand-bound, complex), ligands, mutations, conditions, and its Cα RMSD to two reference chains after core superposition. `closure` is 0 when the chain is like the first reference and 1 when it is like the second. The note at the top of each table gives the reference chains, the residue ranges and their sources. For CypA, RNase A and K-Ras the tables also give side-chain rotamers and alternate conformers.

## `relaxdb_data_issues.md`

Problems we found in RelaxDB entries while we built the atlas: wrong UniProt accessions, units, error columns, temperatures. None of them is confirmed by the RelaxDB authors.

## `error_log.json`

Every pipeline error we found, with its evidence, the fix and the status. IDs go from E-001 upward.
